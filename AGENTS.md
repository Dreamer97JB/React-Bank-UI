Project Context
This repository contains a React front-end for a banking exercise with CRUD screens for Clientes, Cuentas, and Movimientos, plus a Reportes view that lists movements by date range and client and allows PDF download. The UI must mirror the provided layout (sidebar navigation, header, page title, search input, primary "New" button, data table).

Non-Functional Requirements
- Use clean code and SOLID principles.
- Provide unit tests with React Testing Library.
- Do not use prebuilt UI frameworks (Material, Bootstrap, PrimeNg, etc.).
- Use English only for code comments and documentation. Do not mix languages or use emojis.
- UI strings must come from the i18n file with Spanish as the default locale and English as an alternative.

Backend Contract (Expected)
Base URLs
- /clientes
- /cuentas
- /movimientos
- /reportes

Clientes
- GET /clientes
  - Response: array of Cliente.
- POST /clientes
  - Request: ClienteCreate.
  - Response: Cliente.
- PUT /clientes/{clienteId}
  - Request: ClienteUpdate.
  - Response: Cliente.
- DELETE /clientes/{clienteId}
  - Response: 204.

Cliente Models
- Cliente (extends Persona)
  - clienteId: string | number
  - nombre: string
  - genero: string
  - edad: number
  - identificacion: string
  - direccion: string
  - telefono: string
  - contrasena: string
  - estado: boolean
- ClienteCreate: Cliente without clienteId.
- ClienteUpdate: same as ClienteCreate.

Cuentas
- GET /cuentas
  - Response: array of Cuenta.
- POST /cuentas
  - Request: CuentaCreate.
  - Response: Cuenta.
- PUT /cuentas/{numeroCuenta}
  - Request: CuentaUpdate.
  - Response: Cuenta.
- DELETE /cuentas/{numeroCuenta}
  - Response: 204.

Cuenta Models
- Cuenta
  - numeroCuenta: string | number
  - tipoCuenta: "Ahorro" | "Corriente" | string
  - saldoInicial: number
  - estado: boolean
  - clienteId: string | number
- CuentaCreate: Cuenta without numeroCuenta if generated by backend.
- CuentaUpdate: same as CuentaCreate.

Movimientos
- GET /movimientos
  - Response: array of Movimiento.
- POST /movimientos
  - Request: MovimientoCreate.
  - Response: Movimiento.
- PUT /movimientos/{movimientoId}
  - Request: MovimientoUpdate.
  - Response: Movimiento.
- DELETE /movimientos/{movimientoId}
  - Response: 204.

Movimiento Models
- Movimiento
  - movimientoId: string | number
  - fecha: string (ISO 8601)
  - tipoMovimiento: "Credito" | "Debito" | string
  - valor: number
  - saldo: number
  - numeroCuenta: string | number
- MovimientoCreate: Movimiento without movimientoId and saldo (saldo computed by backend).
- MovimientoUpdate: MovimientoCreate.

Reportes
- GET /reportes?clienteId={id}&fechaInicio={YYYY-MM-DD}&fechaFin={YYYY-MM-DD}
  - Response:
    - data: ReporteMovimiento[] (table rows)
    - pdfBase64: string (optional, if bundled)
  - Alternate contract: if PDF is not bundled, backend should expose:
    - GET /reportes/pdf?clienteId=...&fechaInicio=...&fechaFin=...
    - Response: { pdfBase64: string }

ReporteMovimiento
- fecha: string
- cliente: string
- numeroCuenta: string | number
- tipo: string
- saldoInicial: number
- estado: boolean
- movimiento: number
- saldoDisponible: number

Error Handling
- Backend should return errors with a message field.
- Frontend must display errors inline and at form level.
- If backend returns "Saldo no disponible", surface the message without modification.

Search Behavior
- Each table page provides a local, quick search filter across visible columns.
- If backend supports server-side filtering, the UI can switch to query params without changing the UX.

Frontend Structure (Senior-Level Proposal)
- src/
  - app/ (routes, layout, providers, app shell)
  - assets/ (static assets)
  - components/ (shared UI: buttons, inputs, table, modal)
  - config/ (constants, env, feature flags)
  - features/
    - clientes/
      - api/ (API clients and DTO mappers)
      - components/
      - hooks/
      - pages/
      - schemas/ (validation)
      - tests/
    - cuentas/ (same structure)
    - movimientos/ (same structure)
    - reportes/ (same structure)
  - hooks/ (shared hooks)
  - lib/ (helpers, utilities)
  - styles/ (global styles, tokens, layout)
  - types/ (shared types and DTOs)

Testing Approach
- Use React Testing Library for components and page flows.
- Mock API clients at the feature layer.
- Focus on validation messages, table rendering, and CRUD flows.

UI Constraints
- Use custom CSS or CSS Modules with design tokens.
- No UI component libraries or prebuilt CSS frameworks.

Localization
- Store copy in `src/lib/i18n.ts`.
- Default locale is Spanish; English is the secondary locale.

Environment and Mocks
- Configure the backend URL in `.env` as `VITE_API_BASE_URL=http://host:port`.
- If `VITE_API_BASE_URL` is missing or the network request fails, the UI loads mock data from `public/mocks`.
- Mock files: `public/mocks/clientes.json`, `public/mocks/cuentas.json`, `public/mocks/movimientos.json`, `public/mocks/reportes.json`.
